# 失败、重试与跳出

目标：不让任何角色在同一个坑里反复打转。卡住时把问题交回给能决定的人，而不是继续试。

## 1. 先判断失败类型

| 类型 | 例子 | 处理 |
|---|---|---|
| 瞬时故障 | 网络抖动、依赖下载失败、环境偶发 | 最多重试 2 次；仍失败按环境问题停 |
| 可修复错误 | 编译错、测试失败、lint 报错 | 换方案修，最多 3 轮 |
| 信息缺失 | 输入没给、需求含糊、契约缺字段 | 不猜，直接停，列清缺什么、找谁要 |
| 结论冲突 | 文档互相矛盾、契约与实现不一致 | 停，按仲裁规则交决策人 |
| 环境或权限 | 跑不了命令、没有凭据、依赖服务不可用 | 停，说明缺什么、用户可以怎么补 |
| 质量返工 | 测试不通过、评审不通过 | 最多 2 轮，仍不过就升级 |

## 2. 预算

| 项 | 上限 | 到上限后 |
|---|---|---|
| 同一动作加同一错误 | 连续 2 次 | 必须换方案或停 |
| 单任务尝试 | 3 次 | 停，写阻塞报告 |
| 修 bug 循环（改 → 测 → 失败） | 3 轮 | 停，交测试和架构师判断 |
| 评审返工（作者 ↔ 评审者） | 2 轮 | 停，由决策人裁定 |
| 连续无进展 | 2 次 | 停 |

预算按任务算，不按角色算。同一个角色换一个任务，预算重新计数。

## 3. 什么算进展

以下任一才算：

- 新增或更新了产出文件
- 原本失败的检查变成通过
- 解决了一个未知：确认了事实、定下了决策
- 缩小了问题范围：定位到具体文件、行、依赖

「又试了一次」「又读了一遍」「换了个说法」都不算进展。

## 4. 跳出协议

任何角色卡住时：

1. 立即停止当前动作，不启动下游任务。
2. 写阻塞报告到 `<文档根>/07-project/blocked.md`，模板 `references/templates/blocked-report.md`。
3. 回报里写清：未完成什么、试过几次、卡在哪、证据、需要谁决定。
4. 编排层收到阻塞后，不再派依赖它的角色，直接向你报告。

## 5. 禁止

- 用同一个命令、同一个补丁反复尝试，指望结果自己变好。
- 把失败包在「基本完成」里。
- 为了绕过阻塞擅自扩大范围、改契约、跳过安全要求。
- 下游角色替上游补产出或猜结论。
- 用相同的 prompt 反复 spawn 同一个 agent，不给新信息。

## 6. 你可以怎么介入

- 随时打断。打断后项目经理给出当前状态、已经试过什么、下一步选项。
- 看到「还在尝试」但没有新文件、没有新结论时，直接要求停止并出报告。
- 阻塞报告里的决策项必须有选项，不能只写「需要支持」。

## 7. 示例

测试连续三次在同一个用例失败：

1. 第一次失败：读日志，定位到空指针，修掉。
2. 第二次同样的空指针：换修复点，加防御性判断。
3. 第三次仍然失败：停止。写报告：用例 ID、三次改动、日志片段、怀疑是测试数据构造问题，需要测试工程师确认数据，或产品确认预期结果。

这时候继续改代码就是死循环。停下来问，比再猜一次便宜。
